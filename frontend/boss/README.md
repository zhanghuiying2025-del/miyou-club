# 咪游社 · 老板工作台

本仓库的运行方式见[双端演示说明](../../README.md)。以下为交接时的原型说明。

基于参考设计图实现的 React 前端交互演示，使用 Vite 与 Lucide 图标。保留固定左侧导航，所有栏目在右侧主内容区切换为独立页面，详情也在同一主内容区展示。支持页面直达、刷新以及浏览器前进/后退。

## 运行

```sh
npm install
npm run dev -- --host 0.0.0.0
```

## 构建

```sh
npm run build
npm run test:sites
```

构建后的静态前端位于 `dist/client/`；同时保留 Sites 兼容的 Worker 构建结构。

## 页面导航

- 首页：`#/`
- 待审批：`#/approvals`；事项详情：`#/approvals/A001`
- 订单与风险：`#/orders`；订单详情：`#/orders/MY-2026-011`
- AI 员工：`#/team`；员工详情：`#/team/EXECUTOR`
- 经营复盘：`#/review`
- 公司制度：`#/rules`
- 其他业务页：`#/intervention`、`#/errors`、`#/logs`、`#/notifications`、`#/settings`

页面切换保留左侧导航，不显示右侧抽屉或遮罩；详情页可通过面包屑或返回按钮回到所属栏目。

## 演示内容

- 三类待处理入口：待审批、需人工介入、运行异常。
- 酒店预算审批：对比三家供应商、调整预算或选择备选。
- 团建方案确认：三套差异化方案选择。
- 优惠申请审批与退回原因。
- 天气变化的人工指导与状态更新。
- 四类 Agent 的任务、暂停/恢复和演示绩效。
- 订单检索、项目阶段与风险详情。
- 审批历史、动态工作日志与 CSV 导出。
- 公司审批闸门与毛利阈值的会话内配置。
- 通知中心、手机导航与演示重置。

## 建议比赛演示流程

1. 首页点击“酒店报价超出预算”的“查看”，核对模拟报价，选择备选酒店并确认。
2. 待审批数量从 3 变为 2，审批历史和首页日志同步更新。
3. 打开“三套团建方案待确认”，选择方案并继续。
4. 在“需人工介入”中给出雨天调整方向，事项数量从 1 变为 0。
5. 查看 AI 员工的工作清单，展示暂停和恢复。
6. 通过左下角设置中的“重置演示数据”恢复初始场景。

## 后端接入位置

所有演示数据及状态集中在 `src/App.jsx`：

- `seedApprovals`、`agents`、`orders`、`seedLogs` 可替换为你们的查询接口。
- `resolveApproval` 对接审批提交接口；由服务端返回审批结果及更新后的订单状态。
- `addLog` 可改为服务端日志，使用 SSE 或 WebSocket 更新首页动态。
- 暂停/恢复、人工指导与制度保存按钮需要分别接入对应的权限校验接口。
- `public/assets/miyou-robot.png` 来自提供的设计参考。中文字体使用 Noto Sans SC 与 Noto Serif SC，网络不可用时回退为系统字体。

当前为前端演示，刷新后状态恢复初始值。界面不会真实调用模型、联系供应商、发送报价、预订、付款或修改后端规则。订单、报价、绩效及成本为模拟数据。
