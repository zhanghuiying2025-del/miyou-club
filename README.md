# 咪游社 · 团建旅行规划一人公司

## 拿到代码怎么运行

准备 **Python 3.12** 和 **Node.js 22.12 或以上版本**（含 npm）。解压或克隆项目后，在包含 `README.md` 和 `requirements.txt` 的项目根目录打开 PowerShell。

### 1. 首次安装并构建

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd --prefix frontend/customer ci
$env:VITE_SHOW_OWNER_DEMO_LINK = 'true'
npm.cmd --prefix frontend/customer run build
npm.cmd --prefix frontend/boss ci
npm.cmd --prefix frontend/boss run build
```

`VITE_SHOW_OWNER_DEMO_LINK` 仅用于演示构建。正式构建前将它设为 `false`，客户端导航就会隐藏老板端入口。

### 2. 配置 AI 模型

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

在 `.env` 里填自己的模型密钥 `LLM_API_KEY`、接口地址 `LLM_BASE_URL` 和模型名称 `LLM_MODEL`，保存后关闭记事本。可以使用 Xiaomi MiMo 或兼容 OpenAI Chat Completions 的接口。

### 3. 启动并打开网页

```powershell
$env:MIYOU_OWNER_PASSWORD = Read-Host '设置本次演示的老板口令'
.\.venv\Scripts\python.exe -m uvicorn src.web_api:app --host 127.0.0.1 --port 8000
```

第一行会请你输入老板口令。看到 `Uvicorn running` 后，保持终端打开，用这台电脑的浏览器访问页面。

| 页面 | 网址 | 怎么进入 |
|---|---|---|
| 用户端 | [http://127.0.0.1:8000/](http://127.0.0.1:8000/) | 打开后创建活动 |
| 老板端 | [http://127.0.0.1:8000/boss/](http://127.0.0.1:8000/boss/) | 输入刚设置的老板口令 |

安装和构建完成后，日常演示直接执行第 3 步。结束时在 PowerShell 按 `Ctrl+C` 停止服务。

## 一、项目介绍

- **公司要卖的产品**是团建旅行方案规划。平台根据客户需求产出行程、预算和待确认事项。
- **我们的最终成果**是一家团建旅行规划一人公司。我们作为开发团队搭建平台，演示一名人类老板如何带着三位 AI 员工经营这家公司。
- **目标用户**是中小型团建的负责人，例如企业行政、人事、团队主管和社团组织者。

## 二、项目形式

| 页面 | 谁用 | 可以做什么 |
|---|---|---|
| **用户端** | 团建组织者 | 填写或上传需求、看 AI 工作进度、确认方案、选报价、模拟付款、查看回执和评价。 |
| **老板端** | 一人公司的老板 | 看经营总览和待办、审批风险和支出、处理卡住的订单、查历史档案，并查看账本和经营复盘。公司运营页还提供模拟调研、获客活动和优惠券管理。 |

老板端首页突出待办和订单进度，订单详情列出需要处理的原因和可执行操作。两个页面共用一套后端，操作的是同一笔订单。供应商、预订、支付和账本金额用于模拟演示。

## 三、项目流程

### 产品业务

客户提交需求 → 策划提出方向 → 客户确认方向 → 履约执行检查条件 → 项目经理整理草案 → 客户确认最终方案。

### 公司运转

登记咨询和来源 → 客户选报价并付模拟预付款 → 老板授权定金并提交模拟预订 → 客户确认交付并付模拟尾款 → 老板授权结清 → 系统记账并保存评价。

需要客户决定的体验变化，例如下雨时是否改室内，由客户确认。重大风险和供方支出由老板处理。AI 任务中断时，系统保存进度，可从已保存的步骤继续。

### 快速演示

用户端创建「北京、15 人、1 天、人均 700 元」的团建，日期选未来一天。确认方案后查询午餐报价，确认条款并付模拟预付款。到老板端「待审批」授权定金并生成回执，再切回用户端确认交付和支付尾款，最后由老板结清并打开「经营复盘」。

## 四、三位 AI 员工的分工

| Agent | 负责什么 | 把结果交给谁 |
|---|---|---|
| **项目经理** | 整理需求、安排任务、把提案和检查结果合成草案，识别需要人决定的问题。 | 给策划派任务，收回履约检查结果，再把草案交给客户；重大风险交老板。 |
| **策划** | 按人数、预算和偏好设计活动方向，根据反馈修改安排。 | 把提案和修改结果交回项目经理。客户确认方向后，由项目经理安排履约检查。 |
| **履约执行** | 检查时间、场地、交通、餐饮和预算能否配合，标明需要核实的资源和风险。 | 把可行性结论和待核实事项交回项目经理。 |

程序负责检查操作权限、执行模拟预订和记录资金流水。老板可在「工作日志」和订单的「案件审计」里查看交接和决策记录。
